# 远程存储与团队同步执行计划

依据 [28 项路线图](remote-storage-team-sync-roadmap.md)。保留原任务 ID；本文件记录依赖、实施批次、验收与真实进度。2026-10-27 用户授权开始长任务。

## 实施边界与决策

- 纯本地读写保持可用，现有 CLI/MCP/备份兼容；不直接同步正在使用的 SQLite/WAL 文件。
- 默认知识快照包含记忆、来源证据、候选、任务及历史/请求回执；代码索引不进入默认快照。来源摘录默认排除；记忆和候选正文仍可能包含用户保存的代码片段，不能承诺自动脱敏所有内容。
- 项目库与 registry 用户规则分库。规则按明确选择导出，保留 supersede 依赖；恢复时重新映射本地项目和规则身份，个人/工作区作用域不得静默扩大。
- 包格式版本、数据库 Schema 版本、远程同步项目身份和本地 projectId 分开。首版是快照包，增量事件格式在 P1 明确定义，不用本地自增 sequence 充当跨机顺序。
- 首期远程后端拟采用 S3 兼容对象存储；先隔离测试，不上传用户真实项目数据。对象不可变，完整对象发布后再更新可见指针，条件写防止并发覆盖。
- 团队阶段采用可信自托管服务解密共享内容，由服务端执行搜索、权限和审核。用户于 2026-10-27 明确选择此方案；远程存储仍加密，服务端密钥管理、租户隔离、撤销与轮换在 P2 验收。
- 凭据、密钥只通过环境引用或明确配置的密钥提供器取得；不写入项目数据库、包、日志或检查点。
- 范围内新增接口、数据结构与测试已获实施授权；实际云环境验证、部署及发布另行记录条件，不把本地模拟通过写成云端验证通过。

## 第一批具体步骤

1. 编写包格式规范：magic/version、manifest 大小、各分片 table/rows/bytes/hash、schema、内容策略、项目映射与规则策略。
2. 新增 `src/storage/remote-pack/`，复用路径授权、SQLite 与错误结构。禁止由包内表名/路径生成任意 SQL 或文件。
3. 一致读取项目知识数据；独立捕获所选 registry 规则，明确两个快照并非全库同一瞬间；有界读取/写入，不一次加载巨型数据库。
4. 校验全部容器与记录，恢复到全新隔离数据库，事务失败回滚；重建派生检索；保留 source_ref/hash，来源索引在目标项目重建。
5. 聚焦测试覆盖版本、分片、类型/引用、现有目标保护、路径、敏感内容范围及往返；再接核心/CLI 与加密。

## 验证与交付规则

- 改动前 `npm run typecheck`；本次初始基线已通过（2026-10-27）。每批先运行对应 `npm test -- <test-file>`，再 typecheck。
- 可交付里程碑执行 `npm test` 和 `npm run build`；涉及搜索或上下文执行 `npm run eval`，新增语言/插件增加有意义的质量用例。
- P0：密码/认证标签/manifest/分片篡改、未知版本、缺失/重复数据、超限输入、空间/写入失败、重试和恢复演练。
- P1：并发、重复、乱序、离线、时钟偏差、崩溃、删除与终态冲突、长期离线设备重新加入。
- P2：角色矩阵、租户隔离、撤销、审核、审计、认证过期、密钥轮换边界。
- UI：真实浏览器刷新后检查长名称/连续编码/路径/错误文本，默认/隐藏/恢复列、横向滚动、展开、窄屏和放大；焦点/悬停/选择与权限含义保持一致。金额统计完整呈现，适用时检查卡片响应布局。
- 分析、主要实现、验证分别写 task_checkpoint，记录 changedFiles、实际命令与结果、风险/阻塞；未完成任务不标完成。
- 发布/推送前遵守现有版本与 PATCH_NOTES 规则。没有发布行为时不凭空递增版本或创建 tag。
