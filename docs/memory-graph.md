# 本地记忆图谱

0.11.0 增加工作台“项目画像 → 记忆关系”和两个 MCP 读取工具。0.11.1 将默认视图改为“知识关联”：先看记忆之间可解释的主题线索，需要核对出处时再切换“来源追溯”。两种视图都从已有 SQLite 记录派生，不需要新的数据库迁移、模型服务或自动审核，不修改原始记忆。

原视图把记忆与来源、任务、目录同时展开，在本库一次只读观察中返回 80 个节点、85 条边，其中 73 条是范围关系。这样的图主要反映记录所在位置，不能据此认为记忆内容已经互相关联。0.11.1 将来源追溯按需展开，并新增基于标题和正文的本地词面关联。

## 两种视图

| 视图 | 节点与关系 | 适合回答 |
| --- | --- | --- |
| 知识关联（默认） | 只显示长期记忆节点，以及 CONTENT_RELATED、SUPERSEDES 关系 | 哪些知识可能在讨论同一主题？哪个决定替代了旧决定？ |
| 来源追溯 | 记忆、来源、真实任务和适用范围节点；显示来源、替代、任务与范围关系 | 这条记忆从哪里来？由哪个任务记录？适用于哪里？ |

默认概览最多从 12 条记忆开始，加少量邻居后总计最多 24 个节点。每个节点最多连接 2 条内容关联，任务摘要默认排除。这些限额帮助控制图的密度；它们不表示全库只有这些记忆。

## 节点与关系

| 节点 | 内容 |
| --- | --- |
| 记忆 | 事实、决定、约束/规则、偏好、经验、问题、假设；来源追溯中可显式包含任务摘要，保留原有类型与状态 |
| 来源 | 明确的来源种类和引用，文件证据含索引绑定、段落行号、摘录和指纹；无法绑定的来源明确标记 |
| 任务 | 本项目真实存在的任务，包含有界的进度与检查点详情 |
| 范围 | 记忆显式记录的模块或路径 scope |

| 关系 | 视图 | 依据 |
| --- | --- | --- |
| CONTENT_RELATED（可能相关） | 知识关联 | 两端标题和正文至少具有 2 个独立词面线索，并能展示连续原文；无向虚线 |
| SUPERSEDES（替代） | 两种视图 | 新记忆的 supersedesId，箭头从新指向旧 |
| SOURCED_FROM（来源于） | 来源追溯 | memory_sources 绑定记录 |
| PRODUCED_BY（由任务产生） | 来源追溯 | sourceRef 为 task:<id>，且对应任务存在 |
| APPLIES_TO（适用于） | 来源追溯 | 记忆显式 scope；不表示同范围的记忆互相支持 |

默认显示活跃记忆。开启“显示过期、冲突及已替代记忆”后可追踪历史，相关节点用不同状态和虚线边框区分。candidate、rejected、deleted 始终排除。没有来源引用的记录使用各自独立来源节点，避免把所有 user 来源误连起来。网页图中的“规则”指项目记忆的 constraint/preference 等类型；独立的全局个人规则和远程团队规则不包含在此图中。

知识关联始终排除任务摘要。来源追溯只有显式启用 `includeSummaries: true` 才包含摘要；摘要作为邻居中心或直接读取节点详情时，也遵守这一开关，不能通过指定 ID 绕过。

## 内容关联如何形成

CONTENT_RELATED 是本地词面线索，不是自动抽取的实体关系。它只比较记忆的标题与正文，不以 reason、来源引用、scope 或共同所在目录作为内容关联的证据。

- 至少需要 2 个独立线索。中文线索至少连续 3 个汉字；英文词项和标识符采用有界提取。嵌套、重叠的 n-gram 或同一标识符的组成部分，不能重复算成多条证据。
- 过滤常见工作用语、通用角色词、Review 模板、任务/记忆 ID、路径与 URL。仅共同出现“完成测试”“项目代码”“frontend/backend”等通用表述不会自动建立内容边。
- 每条内容边返回 `sharedTerms` 和两端 `excerpts`。每端摘录都是不超过 240 字符的连续原文，含两个线索；不会拼接多个片段制造引文。无法保留适当上下文时放弃该边，不能为了凑匹配而省略否定语境。
- 共同词项只表示可能讨论同一主题，不证明依赖、支持、因果、同意或事实一致；相反结论也可能讨论同一主题。网页不展示关联概率或可信度分数，也不据此修改原记忆置信度。

该机制没有自动实体识别、同义理解、跨语言语义检索或矛盾判定能力。共同词面线索仍可能误连，改写表达也可能漏连；应使用原文和来源做最终判断。

## 网页使用

1. 选择本机项目，进入“项目画像 → 记忆关系”。
2. 默认进入“知识关联”，可搜索主题，分别显示/隐藏“可能相关”和“替代”。
3. 点击图节点或下方可用键盘操作的节点列表查看内容；点击连线或详情内关系按钮查看依据。
4. 选择记忆后用“展开一层/两层”查看局部邻居；点“追溯此记忆”切换到来源追溯并保留该记忆作为中心。切回知识关联会清除来源节点中心。“回到概览”清除搜索与邻居中心。
5. 来源追溯可筛选四类原有记录关系，并按需勾选“包含任务摘要”。记忆详情始终保留来源和范围文字，不必为了看出处让所有来源节点挤进知识视图。
6. 画布支持缩放、平移和适应。网格和短标签避免重叠；自动适应保持可读字号，超出视口的节点可通过平移或下方列表定位。详情读取完整名称，超出服务端硬上限时明确提示截取。节点列表默认展开，可折叠恢复和独立滚动。

页脚“当前展示 X 个节点、Z 条关系”对应本次返回数据；“本项目可浏览 Y 条记忆（含/不含摘要）”对应全库生命周期与摘要开关条件。Y 不随关键词 query 改变，也不是搜索命中总数或图中的来源/任务节点总数。

切换项目、筛选或搜索时清空旧结果并取消待处理请求，过时响应不能覆盖新项目。加载失败支持刷新，空项目与无搜索结果有明确提示。页面只读，不会通过点选节点改变记忆状态。

## MCP

```json
{
  "name": "memory_graph",
  "arguments": {
    "projectId": "prj_example",
    "view": "knowledge",
    "query": "备份规则",
    "depth": 1,
    "limit": 24,
    "includeSummaries": false,
    "includeInactive": false
  }
}
```

`memory_graph` 支持 `query` 或 `nodeId`；传 nodeId 时围绕该节点展开，depth 为 1 或 2。`view` 默认 knowledge，来源/任务/范围节点必须在 evidence 视图展开。可选 relationTypes 只能包含当前视图支持的关系；省略代表该视图的默认关系，空数组代表不显示边。

返回 `view`、`nodes`、`edges`、`root`、`truncated`、`counts` 和 `totals.memories`。counts 是当前返回的节点/边数；totals.memories 只按生命周期和摘要开关统计全库记忆，不应用 query、nodeId、深度或关系筛选。节点 ID 应直接复用返回值，来源与范围使用规范编码。

从 0.11.0 升级后，无参数调用会从来源关系概览改为知识关联，默认 limit 从 80 改为 24，摘要从隐含可见改为默认隐藏。依赖旧来源视图的调用方应显式指定 evidence；需要摘要时再显式开启：

```json
{
  "name": "memory_graph",
  "arguments": {
    "projectId": "prj_example",
    "view": "evidence",
    "nodeId": "memory:mem_example",
    "depth": 2,
    "limit": 24,
    "includeSummaries": true,
    "relationTypes": ["SOURCED_FROM", "SUPERSEDES", "PRODUCED_BY", "APPLIES_TO"]
  }
}
```

```json
{
  "name": "memory_graph_node",
  "arguments": {
    "projectId": "prj_example",
    "nodeId": "memory:mem_example",
    "includeInactive": true,
    "includeSummaries": false
  }
}
```

节点详情按类型包含 memory、task、source 或 scope。来源证据仅从当前项目数据库读取，不会按请求路径读取磁盘文件。项目不存在、节点不在当前项目或不符合生命周期筛选时拒绝访问。两个 MCP 读取入口均刷新调用前托管的待处理索引。

工作台对应 HTTP 路由为 `GET /api/projects/:id/memory-graph` 和 `GET /api/projects/:id/memory-graph/nodes/:nodeId`，复用现有本机认证与 Origin 检查。图谱路由支持 `view=knowledge|evidence`、`includeSummaries=true|false`；详情路由也支持 includeSummaries，默认 false。HTTP 邻居参数名为 node，关系用重复的 relation 参数；所有关系不选时使用 relation=none。两种接口均严格校验视图、关系和布尔值。

## 用于任务上下文

`project_context` 先执行原有词项召回，再最多取 5 条非摘要记忆作为种子，先沿明确来源或真实任务补充，剩余名额再使用内容关联，两路合计最多补充 4 条活跃、非摘要记忆。每个补充目标都必须同时满足：

- 自己的标题/正文与当前任务有足够主题线索：至少 2 个独立线索，或一个复合标识符，或一个至少 4 字的中文线索；
- 原有 scope 适用范围检查；
- 当前生命周期有效，且尚未直接召回。

因此，0.11.0 中“与命中记忆同来源但内容和当前任务无关”的补充，现在会被排除。仅仅同目录或同一次会议不够。图补充低于直接命中的记忆排序；同来源路径保留：

```json
{
  "graphRecall": {
    "fromMemoryId": "mem_seed",
    "viaNodeId": "task:task_example",
    "relation": "same-task"
  }
}
```

支持 same-source、same-task、supersedes。共享文件证据必须具有相同引用、行号与段落指纹，并仍绑定当前索引哈希；缺失或变化的文件不作为扩展依据。任务摘要在图召回候选限额前排除，候选范围检查在最终结果名额前执行。scope 关系不参与自动扩展。过期结论不会因图连接重新成为有效知识。

内容关联补充另带可检查的词项和原文：

```json
{
  "graphRecall": {
    "fromMemoryId": "mem_seed",
    "viaNodeId": "memory:mem_seed",
    "relation": "content-related",
    "possiblyRelated": true,
    "sharedTerms": ["database", "backup"],
    "excerpts": {
      "source": "Database backup retention keeps seven snapshots.",
      "target": "Database backup recovery uses a verified snapshot."
    }
  }
}
```

graphRecall 附在被补充的记忆或 relevant 命中上。“同来源”只说明共同出处，possiblyRelated 只表示词面关联，均不证明结论彼此支持。是否形成内容边与是否进入某次任务上下文是两项判断；图中可见邻居不保证进入当前上下文，最终仍受任务相关性与 Token 预算约束。

## 数量和成本边界

- API 节点默认24、最大150；网页固定请求24。概览和搜索最多12个起始节点，深度最多2；知识视图每节点最多2条内容关联，整体仍受节点与最多450条关系的硬上限约束。
- 单节点邻居最多150，单记忆来源/范围最多24，来源详情最多16份绑定。达到结果上限时返回 truncated，且不返回悬空边。深度是调用者选定的观察范围，不代表全图。
- query 最多200字符，nodeId 最多8192字符。节点标签最多240字符，长内容可从详情读取；过长详情有独立 truncated 提示。
- 图召回内部来源候选亦有上限，大量同来源记录仍可能挤出后面的知识。超长而不可寻址的来源 ID 不进入 graphRecall。
- 内容关联每次最多12个种子，每个种子最多64个查询词项，FTS与汉字索引各取最多128条候选；标题与正文最多检查8000字符。长内容或候选截断时保守返回 truncated；部分有用关联仍可能被限额排除。
- 无新增查询索引迁移；复用现有主来源/文件来源索引，反向替代按层批量查询。scope、部分非文件来源和附加任务绑定查询仍可能扫描相关表，结果数量上限不保证 SQL 耗时恒定。

0.11.0 的历史性能记录：隔离合成内存库（20,000条记忆、20,000条独立会议来源，七次中位数）中，两层80节点查询约53.43ms，五种子无匹配图召回约9.02ms。该记录不包含0.11.1新增的内容关联计算，也不是用户真实大库或服务器负载实测，不能作为新版本或生产性能承诺。

构建并重启 Web/MCP 后生效；stdio MCP 由所属客户端重连，浏览器刷新只能更新已重启服务提供的页面，不能替换后台旧代码。无数据库迁移；远程团队服务保持原有行为。
