# 本地记忆图谱

0.11.0 在工作台“项目画像 → 记忆关系”提供本地知识图谱，也通过两个 MCP 工具读取。它从已有 SQLite 记录派生，不需要新的数据库迁移、模型服务或自动审核，不修改原始记忆。

## 节点与关系

| 节点 | 内容 |
| --- | --- |
| 记忆 | 事实、决定、约束/规则、偏好、经验、问题、假设、任务摘要；保留原有类型与状态 |
| 来源 | 明确的来源种类和引用，文件证据含索引绑定、段落行号、摘录和指纹；无法绑定的来源明确标记 |
| 任务 | 本项目真实存在的任务，包含有界的进度与检查点详情 |
| 范围 | 记忆显式记录的模块或路径 scope |

| 关系 | 依据 |
| --- | --- |
| SOURCED_FROM（来源于） | memory_sources 绑定记录 |
| SUPERSEDES（替代） | 新记忆的 supersedesId，箭头从新指向旧 |
| PRODUCED_BY（由任务产生） | sourceRef 为 task:<id>，且对应任务存在 |
| APPLIES_TO（适用于） | 记忆显式 scope；不表示同范围的记忆互相支持 |

默认显示活跃记忆。开启“显示过期、冲突及已替代记忆”后可追踪历史，相关节点用不同状态和虚线边框区分。candidate、rejected、deleted 始终排除。没有来源引用的记录使用各自独立来源节点，避免把所有 user 来源误连起来。网页图中的“规则”指项目记忆的 constraint/preference 等类型；独立的全局个人规则和远程团队规则不包含在此图中。

## 网页使用

1. 选择本机项目，进入“项目画像 → 记忆关系”。
2. 搜索记忆关键词，或者直接查看概览。四类关系可分别显示/隐藏。
3. 点击图节点或下方可用键盘操作的节点列表查看内容；点击连线或详情内关系按钮查看依据。
4. 选择节点后“展开一层/两层”，继续追查来源、共同来源的记忆及替代历史。“回到概览”清除搜索与邻居中心。
5. 画布支持缩放、平移和适应。为避免长标签重叠，画布使用有间距的网格和短标签；详情读取完整名称，超出服务端硬上限时明确提示截取。节点列表默认展开，可折叠恢复和独立滚动。

切换项目、筛选或搜索时清空旧结果并取消待处理请求，过时响应不能覆盖新项目。加载失败支持刷新，空项目与无搜索结果有明确提示。页面只读，不会通过点选节点改变记忆状态。

## MCP

```json
{
  "name": "memory_graph",
  "arguments": {
    "projectId": "prj_example",
    "query": "备份规则",
    "depth": 1,
    "limit": 80,
    "includeInactive": false
  }
}
```

`memory_graph` 支持 `query` 或 `nodeId`；传 nodeId 时围绕该节点展开，depth 为 1 或 2。可选 relationTypes 包含上述关系名；省略代表全部，空数组代表不显示边。返回 `nodes`、`edges`、`root`、`truncated` 和 `counts`（当前返回数量，不是全库总数）。节点 ID 应直接复用返回值，来源与范围使用规范编码。

```json
{
  "name": "memory_graph_node",
  "arguments": {
    "projectId": "prj_example",
    "nodeId": "memory:mem_example",
    "includeInactive": true
  }
}
```

节点详情按类型包含 memory、task、source 或 scope。来源证据仅从当前项目数据库读取，不会按请求路径读取磁盘文件。项目不存在、节点不在当前项目或不符合生命周期筛选时拒绝访问。两个 MCP 读取入口均刷新调用前托管的待处理索引。

工作台对应 HTTP 路由为 `GET /api/projects/:id/memory-graph` 和 `GET /api/projects/:id/memory-graph/nodes/:nodeId`，复用现有本机认证与 Origin 检查。HTTP 邻居参数名为 node；所有关系不选时使用 relation=none。

## 用于任务上下文

`project_context` 先执行原有词项召回，再最多取 5 条非摘要记忆作为种子，沿明确来源或真实任务补充最多 4 条活跃、非摘要记忆。图补充低于直接命中的记忆排序，每条带有：

```json
{
  "graphRecall": {
    "fromMemoryId": "mem_seed",
    "viaNodeId": "task:task_example",
    "relation": "same-task"
  }
}
```

支持 same-source、same-task、supersedes。共享文件证据必须具有相同引用、行号与段落指纹，并仍绑定当前索引哈希；缺失或变化的文件不作为扩展依据。任务摘要在图召回候选限额前排除，候选范围检查在最终结果名额前执行。scope 关系不参与自动扩展。过期结论不会因图连接重新成为有效知识。

“同来源”只说明共同出处，不证明结论彼此支持，也不解决事实冲突。本模块没有自动实体抽取、语义关系推断或矛盾识别。

## 数量和成本边界

- 节点默认80、最大150；关系最多450；概览和搜索最多40个起始节点；深度最多2。
- 单节点邻居最多150，单记忆来源/范围最多24，来源详情最多16份绑定。达到结果上限时返回 truncated，且不返回悬空边。深度是调用者选定的观察范围，不代表全图。
- query 最多200字符，nodeId 最多8192字符。节点标签最多240字符，长内容可从详情读取；过长详情有独立 truncated 提示。
- 图召回内部来源候选亦有上限，大量同来源记录仍可能挤出后面的知识。超长而不可寻址的来源 ID 不进入 graphRecall。
- 无新增查询索引迁移；复用现有主来源/文件来源索引，反向替代按层批量查询。scope、部分非文件来源和附加任务绑定查询仍可能扫描相关表，结果数量上限不保证 SQL 耗时恒定。

隔离合成内存库（20,000条记忆、20,000条独立会议来源，七次中位数）中，两层80节点查询约53.43ms，五种子无匹配图召回约9.02ms。这不是用户真实大库或服务器负载实测，不能作为生产性能承诺。

构建并重启 Web/MCP 后生效；stdio MCP 由所属客户端重连。远程团队服务保持原有行为。
