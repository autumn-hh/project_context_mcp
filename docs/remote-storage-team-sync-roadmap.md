# 远程存储与团队同步实现任务表

> 初始规划 2026-10-26；2026-10-27 P0–P3 首版功能已落地，按本文标注范围验收。实际顺序、验收证据与限制以 [执行计划](remote-storage-team-sync-execution-plan.md) 为准。
> 对应产品路线：P0 加密远程备份 → P1 单用户多机同步 → P2 团队 ACL 与冲突 → P3 共享索引与增强。
> 交互对照页（可选）：会话内任务表 Page；以本文档为仓库权威清单。

## 原则与边界

- 默认仍可**纯本地**运行；Git 仍是源码真相。
- 远程优先同步**记忆、任务、规则与元数据**；巨型代码索引可选不同步，或按需在目标机重建。
- **不**静默上传源码全文。
- 远程失败须可**降级**为本地读写。
- 正式记忆仍可配置审核策略（候选人工接受）。
- 复用现有能力：AES-256-GCM 加密备份、JSONL 导出、任务 append-only 历史、记忆 supersede 链、候选审核。

## 市面对标（简要）

规划时参考但不绑定实现：

- Cursor Memories 已弱化，Rules / AGENTS.md 为主；跨客户端 MCP 项目记忆仍是空档。
- GitHub Copilot Memory（预览）：仓级共享事实 + 过期策略，团队同步对标信号。
- Cognee MCP：知识图记忆 + 代码搜索，可本地或 API 共享图。
- Mem0 / Zep / Vibsync / Mono Memory 等：托管或 HTTP 共享记忆，多数无本仓库级「索引 + 任务检查点」深度。

本表记录首版交付。OIDC、后台实时同步、二进制索引导入、内置向量模型及生产部署不属于已验收能力；限制见执行计划和功能文档。
